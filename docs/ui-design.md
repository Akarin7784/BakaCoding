# BakaCoding 桌面端前端详细设计（定稿 v1.0（Eva 2026-10-18 批准））

> 状态：草案，待 Eva 确认。确认后以 `docs/ui-design.md` 进仓库，并同步改 `docs/product-design.md` 第 16 节。
> 基线：main `024ccc2`（`packages/desktop`，electron-vite-react + Tailwind v4 + shadcn/ui + lucide）。
> 风格：扁平、简约，交互骨架参考 Claude desktop（左侧会话栏 + 居中单栏对话 + 底部输入框 + 按需打开的右侧面板 + 弹层式设置）。只借布局和交互，不照搬它的品牌色、字体和图标。

## 0. 为什么要重做

现在的界面是按功能一张张单子补出来的，没有整体设计，真机上暴露的问题：

1. **没有"首次使用"流程**：没选仓库时退回到 exe 所在目录当仓库，直接进只读；缺 `config/` 只给一行报错。
2. **状态信息散在顶部横条**：只读原因、同步状态、动作结果、数据库状态都是顶部一行小字，互相覆盖，原因不完整（如 `启动失败（Error）`）。
3. **设置只读、入口藏在主管对话里**：看不到模型、预算、项目配置，也改不了。
4. **项目群、需求话题、PR、Git 信息割裂**：右栏和群消息之间跳转弱，看不出一张单走到了哪一步。
5. **视觉规范只有几个色值**，没有字号、间距、圆角、状态色、空状态的统一规则。

## 1. 设计原则

- **简单好用（Eva 定）**：用户需要的准备工作都在界面里点一下完成，包括初始化 Git、建 main 分支、生成模型配置、填密钥。不要求用户开终端或手抄文件。
- **写用户仓库必须确认**：任何会改用户仓库或系统设置的动作（init、提交、建分支、写配置、写环境变量）都只在用户点击后执行，先弹确认框写明将执行的命令或写入的文件；不自动修。"全部修好"弹一个确认框，列出全部将要执行的步骤。

- **一个焦点**：中间永远只有一个主内容（一段对话或一个项目），其余都是可收起的辅助面板。
- **先能用再好看**：每个页面都要有空状态、加载态、错误态、只读态四种样子，缺一不可。
- **错误说人话 + 给下一步**：每条错误都写"出了什么事 / 为什么 / 点哪里解决"，技术细节折叠在"详情"里，详情已脱敏。
- **扁平**：不用渐变、不用装饰性阴影；分区靠留白和 1px 细线；只有弹层（菜单、设置、对话框）用一层极淡的阴影区分层级。
- **单一强调色**：强调色只用于链接、焦点框、选中态和"正在运行"类状态（主按钮是深色实心，见 5.3）；其它状态用中性色 + 图标形状区分，红色只给"需要你处理"。

- 窗口最小 960×640；宽度 < 1200 时右面板改为覆盖式抽屉，< 1024 时左栏自动收起。

- 全局快捷键：`Ctrl+N` 新需求、`Ctrl+K` 搜索/跳转、`Ctrl+,` 设置、`Ctrl+B` 收起左栏、`Ctrl+.` 开关右面板、`Enter` 发送、`Shift+Enter` 换行。

## 3. 信息结构（相对 product-design 第 16 节的改动）

| 现在 | 改成 | 理由 |
|---|---|---|
| 左栏：主管 + 项目群（群下是可折叠话题） | 左栏：主管 + 项目，项目展开显示需求列表，需求点开即进入该需求的话题视图 | 接近 Claude 的"会话列表"，一层层点进去，不在一个长群里翻 |
| 项目群是一条长消息流 | 项目页 = 需求列表总览；需求页 = 该需求的时间线（派单、编码、评审、复投、合并） | 话题本身就是一个"会话"，单独成页更清楚 |
| 配置入口在主管对话里，只读 | 独立设置弹层（多标签），可编辑并写回 `config/models.json` | 用户反馈看不到也改不了配置 |
| 状态全挤在顶部横条 | 拆成三类：全局状态（左栏底部状态点 + 状态弹层）、页面横幅（只读/缺配置，带操作按钮）、操作结果（右下角轻提示 toast，5 秒消失，错误不自动消失） | 不再互相覆盖 |
| 诊断导出在主管对话和右栏 | 设置 › 诊断 统一入口；需求页右上角"⋯"菜单保留单张导出 | 入口好找 |

**不变的原则**：用户只能在主管对话里发消息；项目页、需求页只读（需求页可以"在主管对话里追问这张单"，一键带上下文跳回主管）。

## 4. 页面与状态

### 4.1 启动 / 欢迎页（新增，替代退回 cwd）

触发：没有 `--repo`、没有 `BAKACODING_REPO`、也没有"上次打开的仓库"（即 T-083 的 `unselected`）。

```
            [机器人图标]
        欢迎使用 BakaCoding
   选一个文件夹开始，BakaCoding 会在里面开分支写代码。

   [ 打开已有项目… ]   [ 新建项目… ]     最近打开：D:\...\MES项目
```

- **打开已有项目**：选任意文件夹，不要求事先是 Git 仓库。
- **新建项目**：选父目录、填项目名，BakaCoding 新建文件夹并完成下面全部初始化。

选完后进入**项目准备**页，逐项检查，每项都有"一键修好"按钮；底部一个"全部修好"按钮按顺序做完所有可自动修的项：

| 检查项 | 不通过时的文案 | 一键修复做什么 |
|---|---|---|
| 是 Git 仓库 | 这个文件夹还不是 Git 仓库 | **初始化 Git**：`git init -b main`；没有 `user.name/email` 时弹一个两栏小表单，只写入本仓库的 `.git/config` |
| 至少有一次提交 | 仓库还没有任何提交 | **创建首次提交**（提交到 main）：文件夹里有文件时，确认框列出将提交的文件（默认排除 `.env`、密钥类文件，规则同第 11 节），因为副 Agent 只能看到已提交的代码；用户也可以选"只做空提交"。空文件夹直接空提交 |
| 有 `main` 分支 | 没找到 main 分支（当前是 master） | **从当前分支新建 main**：只新建，不改名、不删原分支 |
| `.bakacoding/` 已忽略 | — | 自动写 `.git/info/exclude`（T-082 的 `ensureExcludeLines`），不改用户的 `.gitignore` |
| 模型配置 | 缺少模型配置 | **生成配置**：写入 `config/models.json`、`config/pricing.json`（默认模板，只补缺的文件），然后直接打开"模型配置向导" |
| 配置校验 | 列出校验错误的字段路径 | 打开设置 › 模型，定位到出错字段 |
| `DEEPSEEK_API_KEY` | 没检测到 DeepSeek 密钥 | **填写密钥**：见 4.6「密钥」，保存后自动重新检查 |
| 数据库可写、没被别的实例占用 | 这个项目已在另一个 BakaCoding 窗口里打开 | 重新检查 |

**模型配置向导**（第一次生成配置后自动弹出，三步）：
1. 服务商：v1 只有 DeepSeek，显示密钥状态，按钮"测试连接"。
2. 角色分配：主管模型（必填，固定最高档）、评审组成员（默认 1 个，可加）、编码模型与档位（默认 low）。每个下拉只列能力表里支持的模型和档位。
3. 预算：总预算（默认 5,000,000 微美元，显示为 $5.00）、单张单上限，下面一句话解释怎么算。

全部通过才进入主界面；失败就停在这一页，**不进入只读模式**。只读模式只留给运行中出问题的情况。所有修复动作写进操作日志，可在设置 › 诊断里查看。

> 需要后端：`project:check`（返回上表每项的 ok / code / 脱敏 detail），由 T-083 + T-084 合并提供。

### 4.2 主管对话（主页）

- 消息样式：用户消息右侧浅灰底气泡；主管消息左侧无气泡纯文本 + 小机器人头像（带星标）。Markdown 渲染、代码块带复制。
- 输入框：底部居中圆角框（radius 16），左下角是**项目选择 chip**（默认上次的项目，可选"不指定"由主管追问），右下角发送按钮（空内容时置灰）。
- 主管回复 `kind` 的呈现：

| kind | 呈现 |
|---|---|
| `answer` | 普通文本 |
| `ask_project` | 文本 + 下方一排项目按钮，点一下等于回复 |
| `decision_saved` | 文本 + 小标签"已记下" |
| `dispatched` | 文本 + 一张"已派单"卡片：需求名、拆出 N 张单，按钮"查看需求"跳到需求页 |
| `split_failed` | 文本 + "重试拆单"按钮 |

- 等待回复时显示三点淡入淡出；失败时消息下方红字"没发出去 · 重试"。
- **历史要落库**：现在主管对话不持久化，重启就空。需要后端 `supervisor:history`（新单）。
- 空状态：一句引导 + 三个示例需求（点一下填进输入框，不直接发送）。

### 4.3 项目页

标题栏：项目名 · 仓库路径（灰字，可点复制）· 模式标签（本地 / GitHub）。

正文是需求列表（按最近活动排序），每行：

```
● 给登录页加验证码          3 张单 · 2 已合入 · 1 评审中      12:40
✓ 修复库存导出乱码          2 张单 · 全部合入                 昨天
! 重构订单状态机            1 张单需要你处理                   昨天
```

顶部一行汇总：进行中 / 需要处理 / 已完成 计数，点数字过滤。空状态："还没有需求，去主管对话里提一个" + 按钮。

### 4.4 需求页（原"话题"）

- 顶部：需求原文（超过 3 行折叠）、拆单时间、主管的拆单推理摘要（默认折叠）。
- 下面是**单子进度条**：每张单一行，显示 9 个状态里当前所处阶段，用横向步骤条：`排队 → 编码 → 评审 → 合并队列 → 已合入`，评审步骤显示"第 N 轮 / 上限"，每一轮的评审结论都能展开查看（数据直接读模块 6 的 `listPrRounds`，不新增接口）；冲突、重新评审作为步骤上的小标记，上报直接整行标红 + "需要你处理"按钮。
- 再下面是**时间线**：副 Agent 回报、评审结论（通过/不通过 + 理由）、复投记录、合并结果。Flash 调用细节默认折叠成一行"Flash 调用 · low · 2.3k tokens · 4.1s"，点开看提示词摘要和输出。
- 高风险 PR 裁决（T-062）从顶部横条挪到这里，作为时间线里的一张待办卡片，"放行 / 拒绝"两个按钮，拒绝需填理由；同时左栏该需求显示红点。
- 右上角"⋯"：导出这个需求的诊断包、导出单张单、在主管对话里追问。

### 4.5 右面板（项目概览）

跟随当前项目；在主管对话里打开时显示输入框里选中的项目。

1. **编码池**一行：`并发 3/8 · 限流 0 · 反压 关`，有反压时整行变强调色。
2. **Git**：当前分支、集成分支 `bakacoding/integration` 领先 main N 个提交、最近同步时间（T-067 的同步状态挪到这里，不再占顶部）、`合入 main` 按钮（仅 `main_merge=user` 时出现，点了弹确认框）。
3. **需求单列表**：状态图标 + 标题 + 复投次数，点开跳到需求页对应单。可按状态过滤。

### 4.5.1 动态（右面板第二个标签，Eva 定：只显示 Agent 之间的消息）

右面板顶部分「概览 / 动态」。动态只显示 Agent 之间互相发的消息，不显示代码、不显示文件读写、不展开提示词原文：
- 数据源：现有 `group_message`（派单、汇报、评审结论、复投、上报），不新增事件。
- 每条：头像、`发送方 → 接收方`、时间、类型标签（派单 / 汇报 / 未通过 / 重写 / 上报）、正文（超过 3 行折叠）。
- 最新在底部，自动滚到底；用户上翻时停止自动滚，出现「回到最新」。右上角按单过滤。
- 底部一行当前状态（如「T-2 编码中 · T-3 评审中」），来自模块 9 新增的单子状态变更事件（步骤条同源，不轮询）。不显示实时 token，转圈旁耗时由前端计时，调用结束后补 token 与费用。不做工具调用事件、不做副 Agent → Flash 消息。
- 面板关着时有新消息，标签上亮一个小点。

### 4.6 设置（弹层，Claude desktop 式左侧标签页）

`Ctrl+,` 或左栏底部齿轮打开，居中弹层 880×600，左侧标签：

| 标签 | 内容 | 可编辑 |
|---|---|---|
| 通用 | 主题（跟随系统 / 浅 / 深）、语言（v1 仅中文）、启动时打开上次的项目 | 是 |
| 项目 | 已导入项目列表（名称、路径、模式本地/GitHub、基线分支只读显示 main）、打开 / 新建 / 移除（只移除记录，不删文件）；每个项目都有"重新检查准备状态"，跳回 4.1 的准备页 | 是 |
| 模型 | 表单式编辑（与向导相同字段）：评审组成员（模型、档位）、**主管模型（必填）**、编码模型与档位（默认 low）、"测试连接"；高级用户可切到"JSON 视图"直接改 | 是，写回 `config/models.json`，保存前跑同一套 validate，错误逐字段标出；保存后**重载**：同一仓库的后端停掉再起来，复用 `backend-switcher` 的切换流程，不用重启应用；只在没有单处于编码、评审、合并队列时执行，有在途单时按钮显示"等当前单跑完后重载"，用户确认后排队，跑完自动重载。v1 不做运行中热替换 |
| 预算 | 总预算、单张单上限、闲时偏好开关、本项目已花费（来自台账） | 是 |
| 密钥 | 每个服务商一行：已设 / 未设、来源（系统环境变量 / BakaCoding 保存）。未设时给一个密码输入框：保存后写入**Windows 用户级环境变量** `DEEPSEEK_API_KEY`（不写仓库、不写配置文件、不进日志和诊断包），后端只从环境变量读，规则不变。界面保存后永不回显，只显示末 4 位；可"清除" | 是 |
| 诊断 | 导出诊断包（选项目 + 时间段/需求/单张单，v1 不提供"包含完整仓库"，只导出脱敏后的日志、事件、diff 片段和配置结构）、打开日志文件夹、最近一次启动错误详情（已脱敏） | — |
| 关于 | 版本号、commit、第三方许可、项目主页 | — |

配置来源（`--config` / `BAKACODING_CONFIG` / 仓库内）在"模型"页顶部显示一行；由启动参数锁定时整页只读并说明原因。

### 4.7 只读模式与错误

- 只读 = 运行中后端起不来或掉线（租约丢失、存储出错）。表现：内容区顶部一条**横幅**（不是小字），浅红底：
  `只读模式：<人话原因>`　[查看详情] [重新连接]
  详情弹层显示脱敏后的错误名、信息、错误码、一层 cause，和日志文件路径。
- 只读时：输入框禁用并显示"只读模式下不能发消息"；裁决、合入 main、导出按钮禁用并有 tooltip 说明。
- 切换项目失败：显示**新项目**为什么失败（修正现在只显示旧仓库原因的问题），旧项目仍可用就留在旧项目，不进只读。
- 操作结果用右下角 toast；错误 toast 不自动消失，带"复制详情"。

### 4.8 全局状态点

左栏底部齿轮旁一个小圆点：灰=空闲、强调色呼吸=有单在跑、红=有需要你处理的事。点开弹出状态卡：后端模式、同步状态、数据库路径、未归属上报数（原"未归属"页并入这里，点进去看列表）。

## 5. 视觉规范

### 5.1 颜色（OKLCH，浅色 / 深色）

| Token | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `background` | `oklch(0.99 0.002 90)` | `oklch(0.18 0.003 90)` | 内容区底 |
| `sidebar` | `oklch(0.97 0.003 90)` | `oklch(0.15 0.003 90)` | 左栏、右面板底 |
| `foreground` | `oklch(0.22 0.005 90)` | `oklch(0.93 0.004 90)` | 正文 |
| `muted-foreground` | `oklch(0.55 0.005 90)` | `oklch(0.65 0.005 90)` | 次要文字 |
| `border` | `oklch(0.91 0.004 90)` | `oklch(0.29 0.004 90)` | 1px 分隔线 |
| `hover` | `oklch(0.95 0.003 90)` | `oklch(0.23 0.003 90)` | 列表悬停 |
| `accent` | `oklch(0.6 0.15 250)` | `oklch(0.72 0.13 250)` | 链接、焦点、选中、运行中（沿用现有蓝；主按钮不用它） |
| `danger` | `oklch(0.58 0.19 27)` | `oklch(0.68 0.17 27)` | 需要你处理、错误 |

中性色带一点点暖调（色相 90，彩度 ≤ 0.005），比纯灰柔和；强调色仍只有一种。

### 5.2 状态表达（形状为主，颜色为辅，色弱也能分清）

### 5.3 字体与排版

- 字体：`"Segoe UI Variable", "Microsoft YaHei UI", "PingFang SC", system-ui`；代码 `"Cascadia Code", "JetBrains Mono", Consolas, monospace`。
- 字号：12（辅助）/ 14（正文、列表、按钮）/ 15（对话正文，行高 1.65）/ 16（页头）/ 20–24（准备页、欢迎页标题）。字重只用 400 / 500 / 600；西文优先 Inter。
- 按钮三种：主按钮（实心深色，每屏最多一个）、次按钮（浅灰底无边框）、危险操作只在确认框里出现。高度 34 / 小号 28，圆角 10 / 8，文字 500 字重。

### 5.4 间距、圆角、层级

- 4px 栅格：常用 4 / 8 / 12 / 16 / 24 / 32。
- 圆角：按钮 10（小号 8）；输入、列表项 8；输入框外框、卡片、弹层 12–16；头像圆形。
- 阴影：只有弹层、菜单、toast 用一层 `0 8px 24px oklch(0 0 0 / 0.08)`；其余全部无阴影。
- 动效：状态变化淡入淡出 150–200ms；面板开合 200ms ease-out；不做弹跳、不做视差。尊重系统"减少动态效果"。

### 5.5 图标

lucide 线性图标，描边 1.5，尺寸 16（列表）/ 20（按钮）。Agent 头像保持现有简约机器人，主管头顶小星。

## 5.6 文案统一

- **文案能短就短**：标题 2–6 个字，说明一句话，按钮 1–4 个字的动词（「提交」「生成」「放行」）。不在界面上解释原理，原理放文档。
- 面向用户的「复投」统一叫 **重写**（内部术语不变）。

- 状态文案以 `packages/types` 的 `TicketStatus` 为准，界面只做映射，集中在一个文案表里。
- `merged` 统一叫 **已合入**（指合入集成分支）；合入 main 单独叫 **已合入 main**。全界面不再出现"已合并"。

## 7.1 重载与密钥的实现约束

- **重载**：见 4.6 模型页。重载后预算当日已用额度从台账恢复，不清零；8、9、10 接口不变。
- **密钥（若 Eva 同意界面填写）**：
  - 写 `HKCU\Environment` 的 `DEEPSEEK_API_KEY`（明文、仅当前用户可读，与手动设置等同），同时更新本进程 `process.env`，再走重载。实现在模块 3。
  - 值只经一次 `secret:set` 调用从界面传到主进程，主进程绝不回传；末 4 位只在保存那一刻算一次。
  - 不进日志、事件、诊断包、崩溃报告、渲染进程状态。
  - 界面写明：已打开的其他程序（如 PowerShell）要重开才能读到新值。
  - 测试：用测试密钥保存后，在日志和诊断包里搜索该值，必须找不到。
